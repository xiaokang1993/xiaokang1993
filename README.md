# xiaokang1993

本账户是一个 AI 服务账户，仓库内的全部操作由 AI 接管。这里写清楚账户的定位和操作规范，Agent 执行任务前先读这份文档。

## 账户说明

本账户承载 AI 服务相关的仓库、文档和自动化流程。代码提交、Issue 处理、PR 评审、文档更新都由 AI Agent 执行，不经过人工逐条操作。

- 账户性质：AI 服务账户，产出全部由 AI 生成并维护。
- 覆盖范围：仓库代码、README 与设计文档、Issue 和 PR 的回复、Release 说明。
- 数据边界：仓库里不放密钥、凭据和私人数据，需要保密的内容留在私有仓库。

## 操作规范

### 提交

- 提交信息遵循 Conventional Commits，用 `feat:`、`fix:`、`docs:` 这类前缀，一行说清改动。
- 一次提交只做一件事，重构和功能分开提交。
- 不改写已推送的历史，不向 `main` 直接 force push。
- 合并前跑完仓库现有的测试和构建，失败不合并。

### 文档

- 每个仓库都要有 README，写清楚用途、安装方式和运行方式。
- 行为变更同步更新文档和 CHANGELOG，不留与实际不符的描述。
- 文档只写已验证的事实，计划中的功能不写进去。

### Issue 与 PR

- 回复 Issue 先复现问题、给出复现条件，再说结论。
- PR 描述写明动机、改动点和验证方式，一个 PR 只解决一个问题。
- 结论无法验证时标注为待验证，不编造引用和数据。

### 安全与权限

- 凭据通过 GitHub Secrets 或环境变量注入，不进代码和提交历史。
- Agent 只持有完成当前任务所需的最小权限。
- 删除仓库、强制推送、发布包、修改账户设置这些不可逆操作，执行前先取得人工确认。

## Agent 运行时

账户级 Agent 规范见 [AGENTS.md](AGENTS.md)（威胁模型、风险分级、留痕与熔断），仓库级开关见 [.agent-config.yml](.agent-config.yml)。当前工作流：

- `agent-issue-triage`：新 Issue 自动打分诊标签，标签走白名单。
- `agent-pr-review`：新 PR 自动初审，只发评论，不改代码不合并。

两个工作流均为只读能力，模型 key 存仓库 secret `LLM_API_KEY`，未配置时静默跳过。`main` 已开分支保护：改动必须走 PR，禁止 force push。

## 例外

结论存疑、涉及资金或对外发布时，以人工判断为准。发现这份说明和实际操作对不上，先改文档，再改行为。
